Challenge

遇到的問題

跨多個團隊維持設計一致性

台北通整合了許多不同的服務，協助建置的外部廠商很多，每家都有自己的設計師。沒有共同的設計規範，平台各區塊的外觀和感受自然會不一致。

具體問題

  • 各廠商各自為政，做出各自的設計
  • 衍生出過多不同的 UI 元件
  • 平台整體的一致性不足
  • 新功能加入時，品質審查困難
Solution

更新並落實設計準則

設計準則：多廠商協作的共同基礎

台北通是一個大型平台，許多外部廠商同時在上面建置功能，各廠商有各自的設計師和工程師。如果沒有共同的設計規範，要維持整個平台 UI 的一致性是非常困難的。

設計準則就是讓所有廠商朝著同一個方向前進的共同基礎。

一開始的準則只涵蓋色彩、字型大小和間距。隨著平台成長，UX 團隊以「使用者行為」為軸心重新整理——不只是外觀，而是用戶如何互動。這讓設計準則從視覺指南變成了真正可用的設計標準。我們透過 Adobe XD 發布，讓所有廠商隨時都能取用。

設計準則的使用方式

  • 作為所有廠商共用的設計語言——橋接 UI 設計與開發之間的落差
  • 每個新廠商或功能團隊，在開工前都以此為參考基準
  • 開發過程中有疑問時，準則提供了明確的決策依據
  • 身為 UX 團隊成員，我協助更新準則，並支援廠商正確使用

在實際專案中落實準則

每個我負責的功能，都以這套準則作為設計標準。開發完成後，我也進行設計審查，確認最終成品符合設計意圖。

Case Studies

1. Touch 功能網站

Results & Impact

成果與反思

專案成果

  • 設計準則成為所有廠商的共同標準，維持整個平台的 UI 品質一致
  • 因為設計規範清晰且容易取用，新廠商上手速度更快
  • 團隊間的設計落差減少，降低了開發過程中的來回修改

我學到的

  • 學到了如何為大型平台建立並落實設計準則
  • 學到了如何在政府專案中與多種不同角色的人合作
  • 作為資深設計師，從畫面提案到向高層簡報，全程負責
  • 良好的團隊合作讓設計品質大幅提升

反思

在大型平台工作，讓我深刻體會到維持設計一致性有多難。設計準則和審查流程，是這件事最重要的工具。

我們的 PM 非常優秀，整個團隊的協作也很順暢。能以一個凝聚的強大團隊形式工作，是很棒的經驗。
